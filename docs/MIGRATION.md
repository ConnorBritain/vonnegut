# Moving from agent-primitives

This is a repository and marketplace change, not a writing-memory migration.
Bundle versions remain prose-author 0.6.0, prose-review 0.3.0 and prose-tell-scan
0.1.1. Existing installations continue to work until you choose to switch.

## Shared data stays where it is

Keep your corpus, profile, preference and history directories unchanged. The
default registry remains `~/.config/prose-author/identities`; registered absolute
paths and `PROSE_IDENTITY_DIR` keep their meaning. Do not put personal data in
this public checkout or an installation cache. Never delete data as part of a
plugin update. Installation alone neither selects an identity nor enables metrics.

## Native plugins

New plugin IDs end in `@vonnegut`, not `@agent-primitives`. Before enabling the new
copies, disable the three old writing plugins in the host's plugin manager. Keep
unrelated agent-primitives bundles and the old marketplace if you use them.
Then follow the [installation guide](../bundles/prose-author/INSTALL.md), verify
the new installation and start a new session. Avoid two active copies of the same
writing skill. If switching fails, disable the new copies and re-enable the old ones.

The Codex installer can replace an unchanged agent wrapper generated by the
agent-primitives installer. It refuses user-authored or modified legacy wrappers;
back those up and reconcile them explicitly. It does not automatically disable
the old marketplace's plugins or remove unrelated plugins.

## Loose files and editor extensions

Back up local skill customizations, then rerun the new checkout's loose-file
installer. Skill names and data paths have not changed. Loose installs replace
selected skill directories, so local edits inside those directories need deliberate
reapplication. Devin-specific bridge instructions are local adaptations, not a
native generation adapter; preserve them when refreshing copied runtime files.

Codex and Claude extensions inside an editor use the installation belonging to
their configured CLI/config directory. Check those paths rather than assuming
the editor has a separate plugin store. A native Pi generation adapter remains
unimplemented; sharing the identity registry does not install an adapter.
