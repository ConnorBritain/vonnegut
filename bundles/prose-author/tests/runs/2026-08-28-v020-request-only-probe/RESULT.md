# Request-only Claude regression — visible ledger pass, semantic boundary fail

This development probe tested prepared commit `ff7083d` on the same Doctorow-profile
ownership essay as the preceding ledger-first failure. It is not acceptance evidence.

The request-only policy materially improved the visible output. Claude completed in
106,016 ms rather than 459,859 ms, emitted one request-supported ledger entry, emitted no
external-memory ledger entries, and recorded the unavailable named-source habit as an
omission. The strict `voice-draft-source/3` transport and deterministic validator passed.

The prose nevertheless introduced factual premises under non-factual labels. The
independent auditor rejected 13 of 33 sentences, including claims about industry
terminology, tractor part recognition, historical licensing and connected-device
adoption, subscription practices, manufacturer intent, policy history, property law, and
regulatory inaction. A closed ledger cannot constrain facts the writer incorrectly calls
reasoning; the independent audit caught them and blocked public assembly.

No critics were run. The result rules out another prompt-only Claude iteration as the
best next step. The same provider-neutral source/3 contract already produced a 26-of-26
audited Codex draft in the prior probe, so the release harness should exercise that clean
Codex path while preserving Claude compatibility and documenting the observed limit.

Claude CLI reported $0.3224 of API-equivalent telemetry across the draft and audit. These
were subscription-backed CLI calls, not evidence of direct API billing.
